# 03 · 数据库技术栈

> **适用**：网页开发项目（MVP / 快速验证 / 想用不想懂）
> **最后更新**：2026-07-29

---

## 🎯 核心理念

**Postgres on BaaS · 声明式权限 · 网页版管理**

不碰数据库服务器——用 BaaS 网页 dashboard 搞定一切，不需要 Navicat / TablePlus 等 GUI 客户端。

---

## ✅ 技术选择

### 数据库

| 维度 | 选择 ✅ | 不选 ❌ |
|---|---|---|
| **DB engine** | **Postgres**（via Supabase）| MySQL / MongoDB / SQLite |
| **Host** | BaaS 托管（云端）| 自建 Postgres on VM / Docker |
| **迁移** | BaaS 网页版（dashboard）| Django makemigrations / Flyway / Liquibase |
| **调试** | Supabase Dashboard（网页）| Navicat / pgAdmin / TablePlus |

### Postgres 高级特性（按需）

| 特性 | 用途 |
|---|---|
| **JSONB** | 存储半结构化数据（扩展字段）|
| **full-text search** | 站内搜索（无需 ElasticSearch）|
| **pg_trgm** | 模糊匹配（ILIKE 加速）|
| **Row Level Security（RLS）** | 声明式行级权限 |
| **Foreign Key + Index** | 关系建模 + 查询优化 |
| **Auto Vacuum** | BaaS 自动维护，不用手动 vacuum |

### 数据调试方式

| 阶段 | 方式 |
|---|---|
| **本地开发** | `supabase start`（Docker 本地 Postgres）+ Supabase Studio（`localhost:54323`）|
| **生产** | Supabase Dashboard（`supabase.com/dashboard`）|
| **SQL 客户端** | Supabase 内置 SQL Editor（不需要外部 GUI）|

---

## ❌ 不引入的技术（反模式）

| 技术 | 原因 |
|---|---|
| MongoDB | 不适合关系型数据（收藏/关注/评论天然是关系）|
| MySQL | 缺 JSONB / full-text search / RLS |
| SQLite | 并发差 / 无网络访问 / 不适合生产 |
| 自建 Postgres | 运维（备份/监控/迁移/升级）全要管 |
| Redis | 早期不需要缓存层 |
| ElasticSearch | 免费版部署复杂，Postgres full-text search 够用 |

## 📐 常见数据模型（MVP 阶段）

### 用户相关

```
users（由 Supabase Auth 自动生成）
  - id (uuid, PK)
  - email
  - created_at
```

### 业务数据（示例）

```
resources（资源/内容）
  - id (uuid, PK)
  - user_id (uuid, FK → auth.users)
  - title (text)
  - description (text)
  - url (text)
  - tags (text[])
  - created_at (timestamptz)
  - updated_at (timestamptz)

comments（评论）
  - id (uuid, PK)
  - resource_id (uuid, FK → resources)
  - user_id (uuid, FK → auth.users)
  - content (text)
  - created_at (timestamptz)

likes（点赞）
  - id (uuid, PK)
  - resource_id (uuid, FK → resources)
  - user_id (uuid, FK → auth.users)
  - created_at (timestamptz)
  - unique(resource_id, user_id)

favorites（收藏）
  - id (uuid, PK)
  - resource_id (uuid, FK → resources)
  - user_id (uuid, FK → auth.users)
  - created_at (timestamptz)
  - unique(resource_id, user_id)

follows（关注）
  - id (uuid, PK)
  - follower_id (uuid, FK → auth.users)
  - following_id (uuid, FK → auth.users)
  - created_at (timestamptz)
  - unique(follower_id, following_id)
```

## 🔐 RLS 策略模板

每张表创建后，在 Supabase SQL Editor 执行：

```sql
-- 开启 RLS
ALTER TABLE resources ENABLE ROW LEVEL SECURITY;

-- 创建策略：只有创建者能修改/删除自己的资源
CREATE POLICY "users_can_manage_own_resources"
  ON resources
  FOR ALL
  USING (auth.uid() = user_id);

-- 创建策略：任何人可以查看已发布的资源
CREATE POLICY "anyone_can_read_published_resources"
  ON resources
  FOR SELECT
  USING (true);
```

---

## ⚠️ 注意事项

1. **不要在应用层写权限判断**——全部丢给 RLS
2. **auth.users 不要自己建**——Supabase Auth 自动生成
3. **UUID 主键**——用 `gen_random_uuid()` 或 `auth.uid()`
4. **时间戳用 timestamptz**——带时区，避免 8 小时差
