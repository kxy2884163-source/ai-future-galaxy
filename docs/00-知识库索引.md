## 🎯 核心原则（做任何决定前先看这条）

1. **想用不想懂** — 帮设计 workflow，不让用户 debug 代码
2. **少让老大选，多帮拍板** — 能 execute 就不 discuss，能 ship 就不 think
3. **绝不自动通过 approval** — 撞墙停下，等老大点头
4. **记忆优先** — 重要决定立刻落盘，下次会话不丢
5. **不囤 tool / skill** — 按阶段切，需要啥才装啥
6. **代码 → 程序员** — 军师不出 exec 写代码，只派活

---

## 🚫 不适用的场景

- 超大型企业应用（> 100 并发 / 强一致 / 金融级合规）
- 完全自托管需求（数据不能上云）
- 5 人以上协作项目（需要更严格的权限管理）
- 实时聊天 / 直播 / 游戏等需要 WebSocket 长连接强交互

## 📂 使用方式

1. 启动新网页项目时，复制整个 `docs/` 到项目根
2. 在 `07-项目启动checklist.md` 里填"项目特定信息"（产品定位 / 目标用户 / 验收标准）
3. 其他 6 个文件**只改技术决策，不改通用原则**
4. 老大拍板推翻某项时：改对应文件的 ✅/❌，标注日期 + 原因

## 🚀 给 Codex 的冷启动语（项目启动第 1 句读这个）

> 每个新项目复制 docs/ 后，Codex 接活前先读这段。完整内容在 01-08 各文件。

**你已经需要知道的**：
- 技术栈在 01-05，老大的决策已经被军师跑过一遍了，**别重复跑**
- 行为铁律在 06，老大拍板的，写代码别违反
- 启动 checklist 在 07，按阶段做，不跨阶段
- 架构级决策（Three.js / anime.js）按需，看 08
- vendor 本地化 Day 0 做，**别用 unpkg.com**

**你不需要做的事**：
- ❌ 重新讨论 BaaS vs 自建（已拍板 Supabase）
- ❌ 重新讨论 React vs vanilla（已拍板 vanilla 零构建）
- ❌ 重新讨论 Tailwind 是否引入（已拍板不引）
- ❌ 重新讨论 CDN 还是本地化（已拍板 Day 0 本地化）

**你需要做的**：
- ✅ 启动前读 docs/ 全部 9 文件
- ✅ 按 07 checklist 推进
- ✅ 报 approval 时**停下来等老大**，别自动过
- ✅ 做完一阶段汇报，等验收再做下一阶段
