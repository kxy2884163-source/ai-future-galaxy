# 08 · 项目架构选择（按需引入）

> **适用**：项目层级的架构决策，**不是所有项目都用，按需引入**
> **最后更新**：2026-07-29
> **拍板依据**：每个项目需求不同，老大拍板选啥就用啥

---

## 🎯 核心理念

**基础前端栈（vanilla HTML/CSS/ES Modules/CDN）所有项目通用**，
**架构级选择（Three.js / anime.js / 其他）按项目需求引入**。

每个项目开干前，先问：
- 要不要 3D？（Three.js）
- 要不要 DOM/CSS 动画？（anime.js）
- 要不要图表？（Chart.js / ECharts）
- 要不要地图？（Leaflet / Mapbox）
- 要不要 PDF 预览？（pdf.js）
- 要不要富文本？（Quill / Tiptap）
- 要不要 Markdown 渲染？（marked / markdown-it）

---

## ✅ 通用加载规范

所有架构级选择**都走 CDN ESM**，零构建：

```html
<script type="module" src="https://unpkg.com/[package]@[version]/[path]"></script>
```

**禁止**：`npm install` 在项目目录 / 本地 vendor 文件。

## 🧱 3D / 动画 / 可视化

### Three.js（3D 场景）

| 维度 | 选择 ✅ | 备选 |
|---|---|---|
| **3D 引擎** | Three.js（unpkg ESM）| Babylon.js / PlayCanvas |
| **加载方式** | `<script type="module" src="https://unpkg.com/three@0.160.0/build/three.module.js">` | — |
| **Skill 包** | threejs-skills（10 个 SKILL.md）| — |
| **典型场景** | 星空 / 3D 导航 / 3D 数据可视化 / WebGL 作品 | — |
| **体积** | ~600KB gzip | — |
| **不适用** | 简单 2D 交互 / 性能要求极高的低端设备 | — |

### anime.js（DOM/CSS 动画）

| 维度 | 选择 ✅ | 备选 |
|---|---|---|
| **DOM/CSS 动画** | anime.js（unpkg ESM）| GSAP / Velocity / Framer Motion |
| **加载方式** | `<script type="module" src="https://unpkg.com/animejs@4.0.0/dist/animejs.esm.min.js">` | — |
| **版本** | v4（ES Module，跟 v3 不兼容）| — |
| **体积** | ~30KB gzip | — |
| **典型场景** | UI 进场动画 / hover 效果 / 滚动触发 / 数字滚动 | — |
| **不适用** | 复杂时间线编排（用 GSAP）| — |

### Three.js + anime.js 协作模式

| 维度 | 说明 |
|---|---|
| **Three.js 职责** | 画 3D canvas（WebGL）|
| **anime.js 职责** | 动 DOM/CSS 元素（按钮、卡片、标题）|
| **命名空间** | 完全分开（`THREE.*` vs `anime()`）|
| **体积叠加** | 可控（Three.js 600KB + anime.js 30KB gzip）|
| **不会冲突** | 一个画 3D、一个动 UI |

---

## ⚠️ 命名陷阱

- `THREE.AnimationMixer`（Three.js）≠ `anime()`（anime.js）——两者都带"动画"，但作用在不同层
- anime.js v4 命名空间：`anime()` 函数，全局调用
- Three.js 命名空间：`THREE.*` 全大写，所有类/常量都从 `THREE.` 起步

## 🤔 选择决策框架

老大要决定要不要引入某个库时，按 4 个问题问：

### Q1: 真的需要吗？
- 如果 vanilla CSS / JS 能搞定 → 不要引
- 如果只是为了 1 个小特效 → 手动写 CSS animation 就行

### Q2: 用 CDN 能搞定吗？
- 能 → ✅ 走 CDN ESM
- 不能（需要本地编译 / 优化）→ ❌ 不引入

### Q3: 体积可控吗？
- < 100KB gzip → ✅ 可以
- 100-300KB gzip → 谨慎，老大拍板
- > 300KB gzip → ⚠️ 评估是否真需要

### Q4: 有现成 skill 支持吗？
- 有 → ✅ 派 Codex 用 skill 开发效率高
- 没有 → Codex 现学 + 文档驱动
